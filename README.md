# بوت هدايا تيليجرام (Stars Gift Bot)

بوت يعرض على المستخدم كتالوج هدايا تيليجرام العادية (غير NFT)، ويرسلها
له فعلياً من رصيد نجوم حساب مضيف (Userbot) — أي أن **المستلم في كل
عملية هو دائماً الشخص الذي يتحدث مع البوت نفسه**.

المشروع مقسّم لقسمين منفصلين منطقياً لكن يعملان في نفس العملية (process)
تحت حلقة asyncio واحدة:

- **الواجهة الأمامية** (`front_system.py`): بوت عادي بتوكن (pyTelegramBotAPI)
  يتحدث مع المستخدم النهائي.
- **الواجهة الخلفية** (`backend_system.py`): تتحدث مع تيليجرام كحساب
  مستخدم حقيقي (Telethon/MTProto) لتنفيذ الشراء والإرسال الفعلي.

---

## لماذا عملية واحدة (asyncio) بدل Threads؟

Telethon غير متزامن (async) أصلاً، و`pyTelegramBotAPI` يوفّر نسخة غير
متزامنة (`AsyncTeleBot`). تشغيل كليهما تحت نفس حلقة الأحداث يجعل استدعاء
`backend_system` من داخل معالِج زر في `front_system` مجرد `await` مباشر،
دون الحاجة لقنوات اتصال (queues) أو أقفال (locks) بين Threads منفصلة.

## الملفات

### `generate_session.py`
يُشغَّل **يدوياً مرة واحدة فقط، محلياً على جهازك** (وليس على Railway).
يسجّل دخول حساب اليوزربوت الحقيقي عبر `StringSession` ويطبع سلسلة نصية
تُنسخ إلى `.env` كـ `SESSION_STRING`. بهذا لا حاجة لأي تسجيل دخول
تفاعلي (رقم هاتف / كود تحقق) عند تشغيل البوت الفعلي على السيرفر — الجلسة
جاهزة مسبقاً.

**تحذير:** `SESSION_STRING` يعطي دخولاً كاملاً على الحساب — لا تشاركه
مع أحد ولا تضعه في أي مستودع كود عام.

### `backend_system.py`
الوحدة الوحيدة التي تتحدث مباشرة مع MTProto (Telethon). لا تعرف شيئاً
عن واجهة البوت.

| الدالة | الوصف |
|---|---|
| `resolve_user(client, value)` | تتحقق من وجود المستخدم عبر username أو id، وتتأكد أن الحساب ليس محذوفاً (`User.deleted`). تُرجع `User` أو `None`. |
| `build_text_with_entities(text, entities)` | تحوّل قائمة تنسيقات بصيغة Bot API (bold, italic, custom_emoji...) إلى `TextWithEntities` المفهوم من MTProto، لإرفاقها كتعليق مع الهدية. |
| `send_gift(client, recipient, gift_id, hide_name, text_with_entities)` | تبني الفاتورة (`InputInvoiceStarGift`)، تتحقق من صلاحيتها عبر `GetPaymentFormRequest` (لا يخصم أي نجوم)، ثم تنفّذ الدفع الفعلي عبر `SendStarsFormRequest`. تُرجع `GiftResult` موحّداً. |
| `_classify_error(e)` | تحوّل نص خطأ MTProto الخام إلى أحد أكواد `GiftErrorCode` (رصيد غير كافٍ، هدية غير موجودة، خطأ غير معروف...). |

`GiftErrorCode`: `USER_NOT_FOUND`, `USER_DELETED`, `GIFT_NOT_FOUND`,
`INSUFFICIENT_BALANCE`, `UNKNOWN` — هذه الأكواد فقط هي ما يصل للواجهة
الأمامية، وليس نص الخطأ الخام.

### `front_system.py`
كل منطق البوت والواجهة والحالة.

**آلة الحالة لكل مستخدم** محفوظة في `SESSIONS` (قاموس في الذاكرة،
"الفقاعة المؤقتة")، وتُمسح بالكامل (`clear_session`) عند التأكيد أو
التراجع أو أي فشل يوقف العملية (مثل عدم العثور على المستلم).

**البوت مقيّد بالكامل على `OWNER_ID`** — أي رسالة أو زر من أي حساب آخر
يُرفض فوراً برسالة "🚫 لست مرخصاً لاستخدام هذا البوت." عبر ديكوريتورين
(`owner_only_message` و`owner_only_callback`) مطبَّقين على كل معالِج في
الملف، دون تنفيذ أي منطق آخر.

مراحل التدفق (`session["stage"]`):
1. `choosing_gift` — عرض كتالوج الهدايا (زرين في كل صف، `style="primary"`،
   مع `icon_custom_emoji_id` إن توفر شرطه)
2. `choosing_target` — تحديد المستلم: "لنفسي" أو "لغيري" (زران أزرقان `primary`)
3. `waiting_target` — (فقط عند "لغيري") بانتظار id أو username المستلم، يُتحقَّق منه عبر `backend_system.resolve_user`؛ فشل التحقق يوقف العملية بالكامل
4. `choosing_hide` — سؤال إخفاء الاسم (نعم أخضر `success` / لا أحمر `danger`)
5. `waiting_comment` — انتظار تعليق نصي أو ضغط "بدون تعليق" (`primary`)
6. `confirming` — ملخّص (يتضمن الهدية والمستلم وإخفاء الاسم والتعليق) + تأكيد (`primary`) / تراجع (`danger`)

| الدالة | الوصف |
|---|---|
| `load_gifts_from_disk()` / `reload_gifts()` | تقرأ `gift.json` من مسار الفوليوم إلى الذاكرة. `reload_gifts` تُستدعى مرة عند الإقلاع، ثم فقط عند أمر `/rgift`. |
| `build_gifts_keyboard()` | تبني لوحة الهدايا: صفان لكل صف، توزيع تلقائي لصفوف جديدة. |
| `build_target_keyboard()` | لوحة "لنفسي / لغيري" بعد اختيار الهدية. |
| `build_hide_name_keyboard()` / `build_comment_keyboard()` / `build_confirm_keyboard()` / `build_start_keyboard()` | لوحات الأزرار لكل مرحلة. |
| `extract_entities(message)` | تحوّل `message.entities` من كائنات telebot إلى قوائم `dict` بسيطة تُمرَّر لاحقاً لـ `backend_system.build_text_with_entities`. |
| `format_summary(session)` | نص ملخّص المراجعة قبل التأكيد، يتضمن نوع المستلم. |
| `_error_message(code)` | تحوّل `GiftErrorCode` لرسالة عربية مناسبة تُعرض للمستخدم. |
| `owner_only_message` / `owner_only_callback` | ديكوريتوران يقيّدان أي معالِج على `OWNER_ID` فقط. |
| `setup(bot, telethon_client, gifts_path, owner_id)` | تُستدعى من `main.py`، تسجّل كل معالِجات الأوامر والأزرار والرسائل. |

**أهم المعالِجات المسجَّلة داخل `setup`:**
- `/start` — يمسح أي جلسة سابقة، يعرض زر "🎁 خذ هدية"
- `/rgift` — لصاحب البوت (`OWNER_ID`) فقط، يعيد تحميل `gift.json`
- `take_gift` → عرض الكتالوج
- `g:<id>` → اختيار هدية، الانتقال لسؤال "لنفسي / لغيري"
- `target:self` → المستلم = صاحب البوت، الانتقال مباشرة لسؤال إخفاء الاسم
- `target:other` → طلب id/username، ثم التحقق قبل المتابعة
- رسالة نصية أثناء `waiting_target` → تحقق عبر `resolve_user`؛ نجاح → الانتقال لسؤال إخفاء الاسم، فشل → إلغاء كامل للعملية
- `hide:yes` / `hide:no` → حفظ الاختيار، الانتقال لطلب التعليق
- `nocomment` أو رسالة نصية أثناء `waiting_comment` → الانتقال للتأكيد (مع حذف رسالة الطلب ورسالة المستخدم لتنظيف المحادثة)
- `confirm` → استدعاء `backend_system.resolve_user` على المستلم المخزَّن ثم `send_gift`، وعرض النتيجة
- `cancel` → حذف الرسالة، مسح الجلسة، العودة لرسالة `/start`

### `main.py`
نقطة التشغيل:
1. `load_dotenv_if_present()` — محمّل `.env` بسيط بدون أي مكتبة خارجية (فقط للتطوير المحلي؛ على Railway المتغيرات تُحقن مباشرة).
2. `ensure_gifts_file(volume_path)` — إن لم يوجد `gift.json` في الفوليوم، تنسخ النسخة الافتراضية المرفقة؛ إن وُجد لا تلمسه إطلاقاً.
3. تهيئة `TelegramClient` بـ `StringSession` من `SESSION_STRING`، وتهيئة `AsyncTeleBot`.
4. `front_system.setup(...)` لتسجيل المعالِجات.
5. `bot.infinity_polling(skip_pending=True)` داخل `async with telethon_client` — يبقي حساب اليوزربوت متصلاً وجاهزاً للاستدعاء عند الطلب طوال عمل البوت. `skip_pending=True` يتجاهل تلقائياً أي رسائل/أزرار وصلت قبل بدء هذا التشغيل.

### `gifts.json`
كتالوج الهدايا، كل عنصر:
```json
{"id": 1, "gift_id": "5170145012310081615", "custum_gift_icon": "5465263910414195580", "prix": 15}
```
- `id`: رقم محلي متسلسل (يُستخدم في `callback_data` لتفادي أرقام الهدية الطويلة)
- `gift_id`: آيدي الهدية الحقيقي في تيليجرام
- `custum_gift_icon`: `custom_emoji_id` الخاص بالهدية (يُستخدم في `icon_custom_emoji_id` على الزر، بشرط أن يملك البوت يوزرنيمات Fragment أو أن يكون مالك البوت مشتركاً Premium — بدون ذلك يُتجاهل الحقل بصمت من طرف تيليجرام)
- `prix`: السعر بالنجوم المعروض على الزر

للتعديل: غيّر الملف يدوياً في الفوليوم، ثم أرسل `/rgift` من حساب `OWNER_ID`.

## ميزة القسائم (Coupons)

ميزة القسائم تتيح لك إنشاء أكواد خاصة تُستخدم في المحادثة الخاصة مع حساب اليوزربوت، بحيث يمكن لأي مستخدم يرسل الكود في الخاص أن يحصل على هدية معينة تلقائياً.

### كيف تعمل
- يدخل صاحب البوت إلى لوحة القسائم من الزر الموجود في الواجهة.
- يختار إنشاء قسيمة جديدة.
- يحدد:
  - الكود الخاص بالقسيمة (مثلاً: العراق أو ABC123)
  - عدد الاستخدامات المسموح بها
  - مدة الصلاحية بالدقائق
- يمكنه أيضاً ضبط الإعدادات العامة التي تُطبق على كل قسيمة جديدة:
  - اختيار الهدية التي ستُرسل عند الاستعمال
  - هل يُخفى اسم المستخدم الذي استخدم القسيمة أو لا
  - هل يُرفق تعليق مع الهدية أو لا

### السلوك عند الاستخدام
- إذا أرسل شخص ما الكود في رسالة خاصة إلى الحساب المضيف، سيتم التحقق من القسيمة.
- إذا كانت القسيمة صالحة ومفتوحة للاستخدام، سيتم استهلاكها لهذا المستخدم.
- سيتم إرسال الهدية المرتبطة بالقسيمة تلقائياً.
- كل مستخدم يمكنه استخدام نفس القسيمة مرة واحدة فقط.
- إذا انتهت صلاحية القسيمة أو بلغت الحد المسموح لاستخدامها، فلن تعمل.

### ما الذي يدعمه النظام
- إنشاء قسائم يدويًا بكود يحدده المستخدم.
- دعم العربية والأرقام والمزيج بينهما.
- دعم التعليق مع إيموجي أو نص مخصص.
- دعم اختيار الهدية مسبقًا من خلال الإعدادات.
- دعم إضافة هدية جديدة مباشرة من خلال لوحة القسائم.

### ملاحظات مهمة
- القسيمة تُستعمل فقط إذا كانت الرسالة في الخاص تحتوي على الكود وحده، دون كلمات أخرى أو مسافات.
- القسيمة لا تُستعمل إلا من خلال الرسائل الخاصة، وليس من داخل البوت نفسه.
- عند إنشاء قسيمة جديدة، يُطبق الإعداد الافتراضي الحالي من لوحة الإعدادات.

## الإعداد خطوة بخطوة

1. **تثبيت المتطلبات:**
   ```bash
   pip install -r requirements.txt
   ```

2. **الحصول على `API_ID` / `API_HASH`:** من https://my.telegram.org

3. **توليد `SESSION_STRING`:**
   ```bash
   python generate_session.py
   ```
   انسخ الناتج إلى `.env`.

4. **إنشاء بوت عبر @BotFather** والحصول على `BOT_TOKEN`.

5. **نسخ `.env.example` إلى `.env`** وتعبئة كل القيم (`BOT_TOKEN`, `API_ID`,
   `API_HASH`, `OWNER_ID`, `SESSION_STRING`, `GIFTS_VOLUME_PATH`).

6. **التشغيل محلياً:**
   ```bash
   python main.py
   ```

7. **على Railway:** أضف Volume واربطه بمسار مثل `/data`، واجعل
   `GIFTS_VOLUME_PATH=/data/gifts.json`، وضع بقية المتغيرات في تبويب
   Variables (وليس ملف `.env`).

## ملاحظات مهمة

- **حد الأزرار:** الحد الرسمي لتيليجرام هو 8 أزرار في الصف و100 زر إجمالاً
  للوحة الواحدة — التصميم الحالي (2 في كل صف) بعيد جداً عن هذا الحد طالما
  عدد الهدايا أقل من 30 كما ذكرت.
- **`style`** يعمل فقط على تطبيقات تيليجرام المحدَّثة بعد 9 فبراير 2026؛
  العملاء الأقدم يرون الزر بلون افتراضي دون خطأ.
- التحقق من صلاحية الهدية يتم فعلياً عبر `GetPaymentFormRequest` وقت
  الشراء نفسه (وليس عبر مطابقة `gift.json` بقائمة كتالوج عامة) — لأننا
  أثبتنا سابقاً أن بعض الهدايا الصالحة قد لا تظهر في نتائج
  `getAvailableGifts`/`getStarGifts` رغم صلاحيتها الفعلية.
- **البوت خاص بـ `OWNER_ID` فقط** — أي شخص آخر يحاول استخدامه (أمر، زر،
  أو رسالة) يتلقى رسالة "غير مرخّص" فوراً دون تنفيذ أي شيء.
